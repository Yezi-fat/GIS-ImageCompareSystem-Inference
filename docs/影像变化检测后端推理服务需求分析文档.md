## 1. 项目背景

影像地图比对系统（TS + React 前端）当前支持将多幅不同时期地图并列展示，供人工比对同一地点影像的差异。为提升比对效率，系统需引入计算机视觉能力，自动完成影像理解并以蒙版形式在地图上标识结果。

系统能力规划为三个递进层次：

1. **要素识别（基础能力）**：对单期影像进行语义分割，识别指定面状要素（森林、草地、雪山覆盖、建筑等）的空间覆盖范围，生成要素蒙版图层。
2. **双期要素差异比对**：对前后两期影像分别识别要素范围，将两期范围同时叠加显示，差异部分（新增/减少）以不同颜色醒目标识，直观呈现要素的消长。
3. **多期时序分析**：传入按时间排序的多期影像，计算各期要素覆盖范围，支持级联叠加展示（如 2015 年要素范围叠加到 2015/2016/2019 各期地图，2016 年范围叠加到 2016/2019 地图，依此类推），形成面状要素随时间演变的完整视图。

**关键前提（V1.3 修订）**：部署环境的推理条件存在三种可能：① 配置了可用的通用推理服务（专用模型推理平台）；② 未配置远程推理服务但服务器有 GPU；③ 既无远程推理服务也无 GPU，仅 CPU。本服务定位为"业务编排服务"——负责影像预处理、Tile 切分与拼接、任务调度、要素范围计算与差异分析、结果矢量化与存储；模型推理本身通过推理引擎适配层执行，**提供方按"远程 → 本地 GPU → 本地 CPU"三级自动解析**（FR-5.6），未配置远程推理服务属于正常部署形态而非故障。

**架构说明**：原"端到端变化检测"能力（V1.0/V1.1 规划的模型直接输出变化蒙版）保留为独立能力路径；V1.2 新增的三层能力基于"**先识别、后比对**"路线，即要素识别为基座，差异比对与时序分析为派生计算。两条路线可并存，前端按使用场景选择。

## 2. 建设目标

1. 提供地图要素范围识别能力：按用户选定的要素类别输出覆盖范围蒙版及矢量化边界。
2. 提供双期要素差异比对能力：两期要素范围叠加展示，新增/减少区域分色标识。
3. 提供多期时序分析能力：N 期影像顺序计算各期要素范围，支持级联叠加与面积变化统计。
4. 保留端到端变化检测能力：抗光照、季节、云影等非语义干扰，输出变化蒙版。
5. 支持大幅面影像的切块推理与结果拼接；支持检测任务管理与历史结果查询。
6. 推理服务独立部署、独立扩缩容，与主系统解耦；推理能力与业务逻辑解耦，本地/远程推理配置化切换。

## 3. 术语定义

| 术语 | 说明 |
| --- | --- |
| 要素（Feature/Element） | 影像中可识别的面状地物类别，如森林、草地、雪山覆盖、建筑、水体等 |
| 要素识别 / 语义分割（Semantic Segmentation） | 对影像逐像素分类，输出每个像素所属要素类别的计算机视觉任务 |
| 要素蒙版（Feature Mask） | 标识某类要素空间覆盖范围的图层（单类别二值图或多类别类别图） |
| 变化检测（Change Detection） | 对同一区域不同时相影像进行对比，识别变化的计算机视觉任务（本系统中分"端到端变化检测"与"先识别后比对"两条路线） |
| 双时相/多期影像 | 同一区域不同时期的影像（T1/T2/…/Tn，按时间排序） |
| 级联叠加 | 多期分析中，将第 i 期要素范围叠加到第 i 期及其后各期地图上的展示方式 |
| Tile | 大幅面影像切分后的固定尺寸小块（如 256×256），供模型分块推理 |
| 推理引擎适配层 | 本服务内部抽象层，统一"执行推理"的接口，屏蔽本地推理与远程推理服务的实现差异 |
| 通用推理服务 | 外部已有的专用模型推理平台，通过 HTTP/gRPC 提供模型推理能力 |

## 4. 用户与使用场景

### 4.1 用户角色

| 角色 | 描述 |
| --- | --- |
| 比对系统终端用户 | 通过 React 前端选定要素、发起识别/比对/时序分析、查看蒙版结果 |
| 系统管理员 | 配置推理提供方、管理模型与要素类别、监控服务运行状态 |

### 4.2 核心使用场景

**场景一：要素范围识别（V1.2 新增）**
用户在前端选择需要识别的要素类别（可多选，如"森林 + 建筑"）→ 选定影像（上传或框选瓦片范围）→ 后端识别各类要素覆盖范围 → 返回按类别着色的蒙版图层 → 前端叠加显示，支持按类别开关图层、查看各类要素面积统计。

**场景二：双期要素差异比对（V1.2 新增）**
用户选定要素类别与前后两期影像 → 后端分别识别两期要素范围并计算差异 → 返回三类图层：① 新图要素范围、② 旧图要素范围、③ 差异图层（新增区域与减少区域分色标识，如新增绿色、减少红色，颜色语义可配置）→ 前端叠加显示，直观呈现"森林减少了哪里、建筑扩张了哪里"。

**场景三：多期时序分析（V1.2 新增）**
用户按时间顺序传入多期影像（如 2015、2016、2019）与要素类别 → 后端依次计算各期要素覆盖范围 → 前端级联叠加：2015 年范围叠加到 2015/2016/2019 三期地图，2016 年范围叠加到 2016/2019 地图，2019 年范围叠加到 2019 地图 → 配合相邻期差异图层与各期面积统计曲线，完整展示森林、草地、建筑群等面状要素的演变过程。

**场景四：端到端变化检测（保留）**
用户选定两期影像 → 变化检测模型直接输出变化蒙版 → 前端叠加显示。适用于未限定要素类别的通用变化发现。

**场景五：历史结果追溯**
用户查看历史任务列表 → 重新加载某任务的各图层与统计数据。

**场景六：推理后端降级**
通用推理服务不可用时 → 熔断、重试；仍不可用时可选降级至本地 CPU 量化模型，结果标记"降级推理"。

**服务间调用关系**：

| 调用方 | 被调方 | 内容 |
| --- | --- | --- |
| gateway | 各 Java 服务 | 路由转发（统一入口，前端无感） |
| analysis-service | task-service | 创建/更新任务、进度上报 |
| analysis-service | Python infer/compute/nlp | 推理与计算（Feign/httpx） |
| analysis-service | 通用推理服务 | 远程模型推理（remote provider） |
| result-service | storage-service | 蒙版/GeoJSON 存取、签名 URL |
| result-service | Python compute-service | 懒矢量化（GeoJSON 导出时现调 /compute/vectorize，V1.7/设计 §3.3.4） |
| config-service | 各服务 /health | capabilities 能力聚合 |
| task-service | RabbitMQ | 任务队列（analysis-service 消费） |

**模型类型说明**：推理层挂接两类模型——① 语义分割模型（要素识别）；② 变化检测模型（端到端变化检测）。两类模型暴露统一的推理接口形态，由 infer-service 承载。

**前后端职责划分（多期时序分析）**：后端负责计算各期要素蒙版、相邻期差异图层、面积统计；**级联叠加（第 i 期蒙版叠加到第 i~N 期地图）为前端渲染逻辑**，后端一次性返回全部图层数据，前端按级联规则组合显示，无需后端为每种叠加组合单独出图。

```yaml
# config.yaml 推理部分（V1.3）
inference:
  provider: auto              # auto / remote / local-gpu / local-cpu
  fallback_to_local: true     # remote 不可用时是否降级到本地
  remote:                     # 可选配置：不填即视为"未配置远程推理服务"，属正常形态
    endpoint: "http://inference-platform.internal:8000/api/v2/inference"   # 完整 URL（协议+主机+端口+路径），代码直调不拼接（见第 3 节约束 10）
    model_name: "change-detection"
    model_version: "v1.2"
    timeout_ms: 30000
    max_retries: 2
    batch_support: true       # 是否支持 Tile 批量推理
  local:
    gpu_enabled: auto         # auto（启动时探测）/ true / false
    model_path_gpu: "/models/changeformer_fp32.onnx"   # GPU 用 FP32
    model_path_cpu: "/models/changeformer_int8.onnx"   # CPU 用 INT8 量化版
    num_threads: 4
    max_input_size: 2048      # 本地 CPU 模式下限制输入规模
```

`provider: auto` 时的三级解析顺序（启动时执行一次，运行期熔断可临时降级）：

1. 配置了 `remote.endpoint` 且连通性检查通过 → 使用远程推理服务；
2. 未配置或不可达 → 探测本地 GPU（CUDA 可用且显存满足模型要求）→ 使用本地 GPU 推理；
3. 无 GPU → 使用本地 CPU 推理（INT8 量化模型）。

服务启动日志与健康检查接口须明确输出最终选定的提供方及判定依据。要素类别相关配置：

```yaml
# config.yaml 新增节选
features:
  catalog:                    # 可识别要素类别目录（与分割模型输出类别对齐）
    - { id: "forest",    name: "森林",   color: "#228B22" }
    - { id: "grassland", name: "草地",   color: "#9ACD32" }
    - { id: "snow",      name: "雪山覆盖", color: "#F0F8FF" }
    - { id: "building",  name: "建筑",   color: "#CD853F" }
  diff_colors:                # 差异分色语义（可配置）
    added: "#00FF00"          # 新增（仅新图有）
    removed: "#FF0000"        # 减少（仅旧图有）
```

### 6.9 自然语言任务解析（V1.3 新增，P2 增强能力）

**设计定位**：本模块只做"理解"，不做"执行"。用户输入自然语言（如"识别四川成都金牛区xx街道的建筑群"），后端将其解析为**结构化指令**返回；地图跳转、瓦片采集、正式分析均由前端调用既有接口（FR-6/7/8）执行，避免后端越界操作前端状态，也避免重复建设分析链路。

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-9.1 | 接收用户自然语言文本，解析为结构化指令：意图类型（要素识别 / 差异比对 / 时序分析）、地理范围（行政区/地名 → 经纬度边界）、要素类别（映射至要素目录）、期次（如"2015 到 2019"） | P2 |
| FR-9.2 | 地理范围解析依赖地理编码服务（地址/地名 → 坐标范围）；支持到街道级；无法解析或存在多个候选时，返回候选列表交由用户选择 | P2 |
| FR-9.3 | 要素描述映射：将自然语言中的要素表述（含修饰语，如"建筑群""雪山"）映射到要素类别目录；无法映射时明确告知用户该要素暂不支持，并列出当前可识别类别 | P2 |
| FR-9.4 | **用户确认环节（强制）**：解析结果须以结构化形式展示给用户核对（位置、要素、期次、意图），用户确认后才进入执行；解析置信度低时强制确认并标注不确定字段 | P2 |
| FR-9.5 | 确认后的执行流程：前端按结构化指令跳转地图至目标范围 → 采集该区域瓦片影像 → 调用 FR-6/7/8 对应接口 → 叠加展示结果 | P2 |
| FR-9.6 | NLU 能力提供方与推理提供方解耦：优先复用通用推理服务平台上的 LLM；无 LLM 环境时提供降级实现（规则模板 + 地名词典匹配），降级实现仅支持固定句式并明确提示能力受限 | P2 |
| FR-9.7 | **NLU 逐请求降级与熔断（V2.2 新增）**：单次解析调用 LLM 超时/5xx/连接失败，或结构化输出校验重试耗尽时，**当次请求自动降级为规则解析**（响应如实标记 `nlu_provider=rule-based`），不得因 LLM 抖动导致整个解析失败；进程内熔断器防止连续故障拖慢服务（默认 60s 内连续失败 5 次断流 30s 后半开试探，参数可配）；降级事件写结构化日志并计数（固定字段 `event=nlu_degraded`） | P2 |
| FR-9.8 | **地理编码失败的部分成功降级（V2.2 新增）**：NLU 解析成功而地理编码失败时，不整体报错——返回部分成功结果（`location=null` + `uncertain_fields` 含 location + `need_confirm=true`），由用户在确认环节手动选定范围（FR-9.4）；仅当意图与位置均无法解析、结果完全不可执行时才返回 LOCATION_UNRESOLVED 错误 | P2 |

**可行性评估说明（需求评审结论）**：本能力可实现，但原始设想中"后端解析后直接令地图跳转、采集瓦片并分析"的表述存在职责越界——地图跳转与瓦片采集是前端能力，后端无法触达；故拆分为"后端解析 → 前端执行"两段式（FR-9.1~9.5）。主要新增依赖为：① LLM 推理能力（NLU）；② 地理编码服务。两者均需在实施前确认可用性，不可用时可整体裁剪本模块，不影响主链路。

## 8. 非功能需求

### 8.1 性能

| 指标 | 远程模式（推理服务有 GPU） | 本地模式（CPU 降级） |
| --- | --- | --- |
| 单 Tile（256×256）推理耗时（分割/变化检测） | 依赖推理服务 SLA（参考 ≤ 200 ms） | ≤ 3 s（INT8 量化模型） |
| 1024×1024 单期要素识别端到端（同步） | ≤ 5 s | ≤ 60 s（建议改走异步） |
| 双期差异比对（1024×1024，异步） | ≤ 15 s | ≤ 3 min |
| 多期时序分析（3 期 × 1024×1024，异步） | ≤ 45 s | ≤ 10 min |
| 4096×4096 影像（异步任务） | ≤ 60 s | ≤ 15 min，进度可见 |
| 本服务自身开销（不含推理，切分/拼接/差异计算/矢量化） | ≤ 2 s（4096×4096 规模）；双期差异逐像素计算 ≤ 1 s | 同左 |
| 服务可用性 | ≥ 99.5%（工作时间，不含推理服务自身不可用时间） | 同左 |

注：多期任务推理调用量与期数 N 线性相关（N 期要素识别 + N-1 组差异为本地计算），指标按 N=3 给出基准，N 增大时按线性外推并在前端明确预期等待时间。

### 8.2 识别与检测质量

| 指标 | 目标值 |
| --- | --- |
| 要素识别单类 IoU（业务测试集，类别级） | ≥ 0.75（森林/草地/建筑）；雪山等光谱特征明显类别 ≥ 0.85 |
| 要素识别整体 mIoU | ≥ 0.75 |
| 差异区域召回率（以两期标注真值为准） | ≥ 85% |
| 虚警率（光照/季节变化误判为要素变化） | 明显低于 absdiff 基线（下降 ≥ 50%） |
| 端到端变化检测召回率 | ≥ 85% |
| 最小可识别斑块 | ≥ 16×16 像素 |
| INT8 量化相对 FP32 精度损失 | ≤ 2 个百分点 |

注：不同要素类别的识别难度差异较大（如雪山的季节性、草地与耕地的光谱相似性），各类别指标以业务测试集实测为准，上表为目标基线。

### 8.3 安全

- 接口鉴权：API Key / JWT，管理接口单独权限控制。**鉴权支持部署级总开关**（`security.auth.enabled`，FR-10.7）：关闭后全部接口匿名可用，适用于全内网受信环境；关闭状态通过 capabilities 接口向调用方明示。
- 单文件上传大小限制（默认 ≤ 100 MB）；多期任务总上传量限制（默认 ≤ 500 MB）；格式白名单（PNG/JPEG/TIFF/GeoTIFF）。
- 输入影像合法性校验；影像处理在隔离容器内执行。
- 影像与结果数据按用户隔离访问（评审 P-09f 明确落地口径）：本期以**接口层按用户过滤**实现——开启鉴权（FR-10.7）时任务列表/详情按创建人过滤、管理员可查全部；关闭鉴权时匿名共享（无身份可隔离，属该部署形态预期行为）。存储层不做 key 前缀隔离（内网单租户，key 含 task_id 天然防碰撞，越权由接口层鉴权拦截）。
- 与通用推理服务之间通信走内网，必要时启用双向认证。

### 8.4 可维护性与可观测性

- 结构化日志：任务 ID 贯穿全链路；多期任务日志带期次标签。
- 监控指标：QPS（分任务类型）、推理耗时分布（分模型类型）、队列深度、失败率、远程调用超时/重试/熔断/降级次数。
- 告警：推理服务不可用、某模型未就绪、队列积压超阈值、本地模型加载失败。

### 8.5 兼容性

- 前端对接：所有蒙版图层均为 RGBA PNG + 地理范围元数据，前端叠加层统一实现一次即可消费全部图层类型（要素/差异/变化）。
- 要素类别目录通过 `GET /api/v1/elements` 动态下发，类别扩展无需前端发版。
- 推理适配层接口在本地/远程实现间完全一致，切换 provider 不引起业务代码与前端变更。

## 9. 数据设计（概要）

**任务表（task）**：task_id、任务类型（feature_extraction / feature_comparison / temporal_analysis / change_detection）、状态、进度（多期任务含期次细分）、输入影像引用与期次标签、选定要素类别、推理提供方、模型名与版本、是否降级、参数、创建/完成时间、错误信息。

**要素类别配置（element_catalog）**：类别 ID、显示名、叠加颜色、对应模型输出类别 ID、启用状态。

**运行配置表（app_config，V1.8 新增）**：config_key、config_group、value、updated_by、updated_at——运行配置与功能开关的持久化载体（FR-10.2）。

**图层表（layer）**：layer_id、task_id、期次、要素类别、图层类型（FEATURE / DIFF / CHANGE / PROBMAP——差异为单张分色图，新增/减少按图例着色；与设计文档 DDL 口径一致，评审 P-09d）、对象存储路径（落库只存 storage key，签名 URL 读取时实时签发）、地理范围。

**区域表（region，V1.7 降级为可选）**：region_id、task_id、期次、要素类别、区域类型（覆盖/新增/减少/变化）、面积、中心点、多边形坐标（GeoJSON）、置信度均值。**默认不启用**——多边形明细以 GeoJSON 文件存对象存储；仅当需要"按空间范围检索变化斑块"类功能时启用。

**时序统计（由结果直接汇总）**：各期各类要素面积序列，随任务结果一并计算并存入 task.result。

**对象存储 / 本地降级存储**：`/{task_id}/{period}/{element}_mask.png`、`/{task_id}/diff_{from}_{to}_{element}.png`、`/{task_id}/probmap.png`、`/{task_id}/regions.geojson` 等。

## 10. 约束与依赖

1. **推理服务依赖（可选，非前置条件）**：未配置通用推理服务属正常部署形态，服务自动降级为本地 GPU/CPU 推理（FR-5.6）。若配置远程模式，则依赖其可用性、性能配额与接口规范，需与平台方确认：语义分割与变化检测**两类模型**的接入流程、HTTP/gRPC 接口规范、批量推理支持、SLA。
2. **模型依赖**：需准备两类模型——① 语义分割模型（如 SegFormer、DeepLab、UNet，基于 LoveDA、SpaceNet 等土地覆盖数据集训练或针对业务数据微调），**其输出类别必须覆盖要素类别目录**；② 变化检测模型（如 ChangeFormer、BIT）。交付要求：远程部署版本 + 本地降级用 ONNX 版本（含 FP32 与 INT8 量化两份）。
3. **要素类别约束**：可识别类别受限于分割模型的训练类别；新增要素类别（如"雪山"）若模型不支持，需补充标注数据并微调，不能仅靠配置扩展。
4. **硬件依赖**：本服务最低运行于普通 CPU 服务器（建议 ≥ 8 核）；如服务器配有 GPU，本地推理自动启用 GPU 路径（FR-5.6），性能指标相应上浮。
5. **坐标系依赖（V1.5 修订）**：系统坐标统一为 **CGCS2000 经纬度投影**（经纬度瓦片方案，非 Web Mercator）。瓦片范围与地理范围按经纬度线性公式换算（瓦片跨度 360/2^z 度；瓦片矩阵原点/起始级定义以实际瓦片服务规范为准并配置化）；双期/多期影像须为同一地理范围（同源同层级瓦片或相同配准参数）；跨源影像依赖配准能力（FR-1.2）；多期任务强制校验（FR-8.7）。地理量算（面积/中心点）采用 CGCS2000 椭球大地测量方法。
6. **与现有系统关系**：本服务仅新增，不改动现有前端比对功能；前端蒙版叠加层复用方案 A 已实现的能力，级联叠加为前端新增渲染逻辑。
7. **NLP 能力依赖（仅 FR-9，可选）**：自然语言任务解析依赖 ① LLM 推理能力（优先复用通用推理服务平台上的 LLM，或自部署开源模型）；② 地理编码服务（地址/地名 → 坐标，支持到街道级）。两者不可用时可整体裁剪 FR-9 模块，不影响 FR-1~FR-8 主链路。
8. **对象存储依赖（可选，V1.7 新增）**：优先使用私有云 OSS/OBS；未配置时自动降级为本地磁盘存储（FR-4.4），系统功能不变，仅容量受磁盘限制——此时 FR-4.3 定期清理与 FR-4.5 空间保护成为关键保障，建议缩短保留期并挂独立数据卷。
9. **注册中心依赖（V2.0 新增）**：微服务架构依赖 Nacos（注册/发现），内网单节点部署即可起步。Python 微服务不接入注册中心，由 analysis-service 以配置地址直连；local 存储模式下 storage-service 限单副本（FR-4.4 约束）。
10. **URL 完整性约束（V2.3 新增）**：所有外部/第三方服务地址类配置项（通用推理服务 endpoint、LLM 接口、地理编码服务、OSS/OBS endpoint）一律配置**完整 URL**（协议 + 主机 + 端口 + 完整路径），服务代码**不得在其后拼接任何固定路径**——内网部署形态各异，无法预知用户的 URL 结构（可能带网关前缀、反向代理路径等）。一个服务需要多个端点时，每个端点独立配置一项。启动时校验各 URL 配置项可解析为绝对地址。例外：系统自有微服务之间的地址（Java 调 Python 三服务）允许配置服务根地址（允许带反代路径前缀），其后的 `/infer/*`、`/compute/*`、`/nlp/*` 路径属本系统内部契约，不属"第三方 URL 结构"。

## 11. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 通用推理服务故障/不可用（含**用户未配置推理服务**的情形） | 远程路径不可用 | 未配置不视为故障：启动时按 FR-5.6 三级自动解析——先探测本地 GPU，有则本地 GPU 推理，无则本地 CPU 推理；运行期故障则超时熔断 + 有限重试 + 降级本地；`/healthz` 明示当前提供方及判定依据 |
| 本地环境探测误判（如有 GPU 但驱动异常未识别） | 性能未达预期/误用 CPU | 探测结果显式输出于启动日志与健康检查；支持管理员强制指定 provider 并告警冲突（FR-5.7） |
| 分割模型输出类别与业务要素目录不匹配（如模型无"雪山"类） | 要素选择不可用 | 类别目录与模型输出建立显式映射（FR-6.2）；前端通过 `/api/v1/elements` 动态获取，不展示不支持的类别；长期靠微调扩展 |
| 自然语言要素表述超出类别目录（含特定修饰语，如"沿街建筑群"） | NLP 入口下要素无法映射 | FR-9.3 明确告知不支持并列出可识别类别；强制用户确认（FR-9.4），不以猜测结果直接执行 |
| LLM / 地理编码服务不可用或解析错误（地名歧义、LLM 幻觉） | NLP 入口结果错误 | 多候选返回由用户选择（FR-9.2）；结构化结果强制确认（FR-9.4）；无 LLM 时降级规则模板 + 地名词典并明示能力受限（FR-9.6）；模块可整体裁剪，不影响主链路 |
| 部分类别识别精度不足（草地/耕地混淆等） | 该类结果不可信 | 分类别验收指标（8.2）；业务数据微调；结果展示置信度提示 |
| 两期/多期影像未对齐 | 边缘伪差异淹没真实差异 | 强制同范围校验（FR-8.7）；配准校验与告警（FR-7.7）；边缘伪差异抑制 |
| 多期任务推理量大、耗时长 | 用户等待焦虑、队列积压 | 异步 + 期次细分进度（FR-2.4/8.6）；Tile 批量推理；限制 N 上限（默认 ≤10）；前端展示预期等待时间 |
| 本地降级模式精度和速度有限 | 降级期间体验下降 | INT8 量化；限制降级模式输入规模与期数；结果明确提示用户 |
| 推理服务接口规范不一致或变更 | 联调失败/线上故障 | FR-5.4 固化两类模型接口规范；适配层吸收差异；契约测试 |
| 模型版本与结果对不上 | 无法追溯问题 | FR-3.3 强制记录 provider + 模型类型 + 版本 |

## 13. 验收标准（摘要）

1. 要素识别：选定"森林+建筑"提交单期影像，返回按类别着色的合成蒙版与各类独立蒙版，前端可叠加、可按类别开关图层，面积统计正确。
2. 双期比对：提交两期影像，返回新图范围、旧图范围、差异三类图层，差异图层中新增/减少区域按配置颜色区分，统计中的新增/减少/净变化面积与图层一致。
3. 多期分析：按 2015/2016/2019 顺序提交三期影像，任务进度按期次细分可见；返回三期各自蒙版、两组相邻期差异图层、面积序列；前端可将 2015 年蒙版级联叠加到 2015/2016/2019 三期地图，叠加位置与地理范围正确。时序颠倒的输入被明确拒绝。
4. 选定类别超出模型支持范围时返回明确错误，不静默忽略。
5. 推理提供方解析：① 未配置远程端点时服务正常启动，按"本地 GPU → 本地 CPU"自动选择，启动日志与 `/healthz` 输出最终提供方及判定依据；② 通过配置强制切换 provider（remote / local-gpu / local-cpu），全部任务类型功能正常且无需改动业务代码；③ 模拟推理服务运行期不可用时，熔断与降级行为符合 FR-5.3，任务结果正确标记降级信息。
6. 每个任务结果可追溯：能查到任务类型、要素类别、实际使用的推理提供方、模型名与版本。
7. 在业务测试集上达到 8.2 节质量指标（分类别）。
8. 服务异常（非法输入、推理超时、推理服务不可用）返回规范错误码，不产生未捕获异常。
9. （如实施 FR-9）输入"识别四川成都金牛区xx街道的建筑群"，返回结构化指令（意图=要素识别、位置含地理编码 bbox、要素=building），且未经用户确认不产生任何分析任务；地名歧义时返回候选列表；无法映射的要素表述明确提示不支持。
10. （FR-10）管理员通过接口修改运行配置（如结果保留期、默认阈值），无需重启即生效且重启后不丢失；非法取值被拒绝并提示；修改产生审计记录。关闭某功能开关后，`/api/v1/capabilities` 返回对应能力为关闭，再次开启后恢复。

## 14. 技术架构选型（V1.4 新增）

### 14.1 总体技术架构

采用 **Java 微服务群（6 个，Spring Cloud）+ Python 微服务群（3 个，FastAPI）** 架构，拓扑详见第 5 章。划分原则不变：Java 管"确定性逻辑"（业务编排、状态流转、数据持久化），Python 管"模型与计算"（推理、数值计算、NLP）。

**核心原则**：gateway 是唯一对外门面（鉴权、限流、审计只在一处）；Python 服务无状态、仅内网可达，只处理"给我影像，还你蒙版"；各服务间以 OpenAPI 契约先行，并行开发；任务状态机归 task-service，FR-8.6 期次细分进度由其维护；FR-5.6 三级提供方解析的判定权与配置权在 analysis-service，Python 接收 provider 提示执行；数据按服务分表自治（task → task-service，layer/region → result-service，app_config/element_catalog → config-service），跨服务只走接口不共享表。

### 14.5 无 PostGIS 的几何数据方案

私有云 PostgreSQL 无扩展安装权限，采用"**数据库只存结果，空间计算全在 Python**"方案：

- **区域多边形**：GeoJSON 文本存 JSONB 列，仅作存储与导出（FR-4.2 直接可用），库内不做空间运算；
- **空间查询**：region 表冗余 `bbox_minx / bbox_miny / bbox_maxx / bbox_maxy` 标量列 + 复合索引，"某范围内查变化区域"即四次数值比较，无需空间索引；
- **面积/中心点**：Python 侧 Shapely 计算后作为标量列（`area_m2`、`centroid_x/y`）入库，FR-6.5/7.5 的地理面积换算在 Python 完成；
- **精确空间关系判断**（低频）：取出 GeoJSON 在 Java 侧用 JTS（纯 Java 几何库）计算；
- **迁移路径**：表结构按"几何 + 冗余标量"设计，未来开放扩展权限后新增 geometry 列即可平滑迁至 PostGIS。

### 14.8 技术栈决策记录（ADR 摘要）

| 决策 | 结论 | 理由 |
| --- | --- | --- |
| 双语言边界 | Java = 业务/数据/门面；Python = 推理/计算/NLP | 按能力本质划分；与 FR-5 适配层同构，接口边界即进程边界 |
| 微服务拆分粒度（V2.0） | Java 6 服务（网关/任务/分析/结果/存储/配置），Python 3 服务 + cv-common | 按业务域拆分、数据分表自治；粒度控制在"一个服务一个明确职责"，避免过度拆分带来的运维成本；对外契约不变，前端无感 |
| Python 包含 NLP | 是 | NLU 本质是模型推理，与地理编码强耦合，Python LLM 生态成熟 |
| Java 不引入地理计算库 | 是 | 几何/像素计算全部下沉 Python，Java 只处理结构化结果，避开 JavaCV/GeoTools 深水区 |
| 对象存储用私有云 OSS/OBS | 是 | 内网私有云已提供；Java 存储抽象接口（put/get/signUrl/delete）+ 双实现，业务无感 |
| 无 PostGIS 用 JSONB + 标量列 | 是 | 私有云无扩展权限；空间计算本就在 Python；bbox 数值列 + 索引覆盖主流查询；预留迁移路径 |
| 队列选 RabbitMQ / 起步不引入 Redis | 是 | 最小依赖起步，均可后加 |
| Java 侧推理调用用 Feign | 是 | 声明式客户端 + Resilience4j 统一实现 FR-5.3 |
