## 1. 交付物清单（每模型每版本）

| 产物 | 文件 | 用途 |
| --- | --- | --- |
| FP32 模型 | `fp32.onnx` | GPU 推理（CUDAExecutionProvider） |
| INT8 量化模型 | `int8.onnx` | CPU 推理（CPUExecutionProvider，本地降级路径） |
| 预处理规范 | Python 参考代码（归一化/通道顺序/Tile 尺寸） | infer-service `pipeline/preprocess.py` 按此实现（P-014） |
| 精度报告 | 量化损失 + 业务测试集指标 | 验收：INT8 相对 FP32 精度损失 ≤2 个百分点（需求 8.2） |

## 2. 模型目录规范（infer-service 挂载卷）

```
models/
├── {model_name}/                 # 如 landcover-seg / change-detection
│   └── {version}/                # 如 v2.0
│       ├── fp32.onnx
│       └── int8.onnx
```

- 引擎按请求携带的 `model_name`/`model_version` **懒加载并缓存会话**（FR-3.5）；
  缺省用 L1 配置 `models.{segmentation,change_detection}.name/version`；
- Java 侧"激活新版本"= 运行配置热生效后逐请求下发名/版本，infer-service 无需重启；
- 模型文件下发：Java 模型登记（POST /api/v1/models）后经对象存储 + 命名卷下发
  （storage_key 与双产物的对应约定待 Java 确认，J-05）；内网交付可由运维直接放置共享卷。

## 3. INT8 量化制作（可复现）

```bash
# 动态量化（无需校准集；权重量化 QInt8）
.venv/bin/python scripts/quantize_int8.py models/{name}/{version}/fp32.onnx
# 产出：同目录 int8.onnx + 张量级精度比对报告（max_abs_err / rmse / rel_err%）
```

- 脚本退出码：最大相对误差 ≤2% → 0，否则 1（需在业务测试集复核）；
- 伪模型（v0.0-fake）为纯计算图无权值，量化零误差，仅用于验证脚本链路；
- 真实模型建议量化前做图预处理（onnxruntime quantization preprocessing，见脚本 WARNING 链接）；
- 业务精度报告（分类别 IoU 等，需求 8.2）由模型团队在业务测试集产出，随模型一并交付。

## 4. 注册与切换流程

```
模型团队交付（FP32+INT8+预处理规范+精度报告）
  → 运维放置共享卷 {name}/{version}/（或经 Java POST /api/v1/models 登记下发）
  → Java PUT /api/v1/models/active 激活（运行配置热生效）
  → 后续推理请求携带新 model_name/model_version
  → infer-service 懒加载新版本会话（ModelStore 缓存）
  → 回滚 = 重新激活旧版本（历史版本保留不删除）
```
